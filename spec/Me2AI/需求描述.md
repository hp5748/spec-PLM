# 第一部分：功能需求

## 1. 项目概述

### 1.1 项目背景
本项目旨在构建一个PLM（Product Lifecycle Management，产品生命周期管理）系统的原型，验证技术架构可行性，展示核心功能，并收集业务部门反馈。

### 1.2 核心目标
- **验证技术架构**：验证Go+Vue3技术栈的可行性与性能
- **展示核心功能**：实现BOM管理、文档管理、流程管理的MVP版本
- **建立开发规范**：形成可扩展的开发框架和团队协作流程
- **用户反馈收集**：获取业务部门对功能的初步反馈

### 1.3 实施原则
1. **敏捷迭代**：2周一个迭代，快速交付可用功能
2. **MVP优先**：聚焦核心价值，避免过度设计
3. **技术债务控制**：保持代码质量，随时可重构
4. **用户参与**：业务用户全程参与原型设计

### 4.5 BOM管理模块

#### 4.5.1 BOM类型说明
BOM管理分为两种类型：
- **精确BOM（Exact BOM）**：父子关系精确到具体编码版本，用于已定型产品
- **非精确BOM（Non-exact BOM）**：父子关系只关联编码（不指定版本），用于设计阶段或通用模板

#### 4.5.2 BOM关系属性
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | bigint | 是 | 主键ID |
| parent_item_id | bigint | 是 | 父编码ID（关联编码表） |
| parent_version | string(2) | 否 | 父编码版本（精确BOM必填，非精确BOM为空） |
| child_item_id | bigint | 是 | 子编码ID（关联编码表） |
| child_version | string(2) | 否 | 子编码版本（精确BOM必填，非精确BOM为空） |
| quantity | decimal(10,4) | 是 | 数量 |
| sort_order | int | 否 | 排序 |
| is_exact | boolean | 是 | 是否精确BOM（true=精确，false=非精确） |
| status | enum | 是 | 拟制中/审核中/已发布 |
| created_by | bigint | 是 | 创建人 |
| created_at | timestamp | 是 | 创建时间 |
| updated_at | timestamp | 是 | 更新时间 |

### 4.6 流程管理模块

#### 4.6.1 流程定义
- 流程类型：BOM审批、文档审批、PART审批等，根据业务进行扩展，不同业务流程模板不一样。
- 流程节点：单节点审批（原型阶段）
- 流程状态：拟制中/审核中/已驳回/已发布/已失效/已删除
- 流程版本：流程模板按照版本控制AA至YY（跳过O/I/Z）

#### 4.6.2 流程实例
- 流程发起（选择业务对象、填写意见）
- 待办列表（我的待办任务）
- 审批操作
  - 同意
  - 拒绝（填写原因）
  - 转交（转给其他人）
- 流程历史查看（操作节点、操作人、意见、操作时间）

#### 4.6.3 脚本注入机制
- JavaScript执行引擎
- SQL脚本支持：以申请单为对象入口开始查询
- 脚本沙箱安全隔离
- 脚本执行意图：用于校验提醒与拦截、用于获取数据范围与设置数据

## 5. 业务规则

### 5.1 版本控制规则
| 对象 | 版本触发条件 | 版本变更规则 |
|------|--------------|--------------|
| 物料 | 发布后修改 | 发布后修改自动升版 |
| 文档 | 重新上传 | 上传新文件自动升版 |
| BOM | 结构变更 | 关联物料发布后锁定 |
| 流程模板 | 节点变更 | 新建版本，旧版本继续可用 |

### 5.2 状态流转规则
```
物料/文档/BOM 生命周期：

[DRAFT] ──发起审批──> [REVIEWING] ──通过──> [RELEASED]
   ▲                      │
   └──── 驳回 ────────────┘
                              │
                              └── 失效 ──> [OBSOLETE]
```

**状态变更权限**：
| 操作 | DRAFT | REVIEWING | RELEASED | REJECTED |
|------|-------|-----------|----------|----------|
| 编辑 | 创建人 | - | - | 创建人 |
| 删除 | 创建人 | - | - | 创建人 |
| 发起审批 | 创建人 | - | - | 创建人 |
| 撤回审批 | - | 创建人 | - | - |
| 通过/驳回 | - | 审批人 | - | - |
| 失效 | - | - | 管理员 | - |

### 5.3 BOM规则
1. **精确BOM**：父子关系必须指定版本，用于已发布产品
2. **非精确BOM**：父子关系不指定版本，用于设计阶段
3. **BOM视图**：同一物料只能有一个BOM视图
4. **循环检测**：禁止创建循环依赖的BOM结构

### 5.4 流程规则
1. **发起条件**：对象状态必须为 DRAFT 或 REJECTED
2. **审批人指定**：支持按角色、按部门、指定人员三种方式
3. **转交限制**：只能转交给有审批权限的人
4. **历史记录**：所有操作必须记录到流程历史

### 7.5 版本规则
```
版本号格式：AA - YY（跳过 I、O、Z）
示例：AA, AB, AC, ... AY, BA, BB, ... YY

规则：
- 新建对象初始版本：AA
- 版本递增：当前版本+1（跳过禁用字母）
- 禁用字母：I（易与1混淆）、O（易与0混淆）、Z（易与2混淆）
- 最大版本：YY（共24*24=576个版本）
```

## 8. 扩展属性规范

### 8.1 属性类型定义
扩展属性分为两种类型：

| 类型 | 存储方式 | 特点 | 使用场景 |
|------|----------|------|----------|
| 主属性 | 主表JSON字段 | 随主对象一起查询 | 常用、固定的扩展字段 |
| 动态属性 | 独立属性表 | 可按类型分组，支持多行 | 可配置、灵活的属性集合 |

### 8.2 主属性（main）
**用途**：扩展主对象的字段，存储在主表JSON字段中

**数据结构**：
```sql
-- 主表中的attributes字段
ALTER TABLE items ADD COLUMN attributes JSON COMMENT '主属性JSON';

-- 存储示例
{
  "weight": 1.5,
  "color": "red",
  "material_grade": "304SS"
}
```

**Schema定义**（前端渲染表单）：
```json
{
  "fields": [
    { "key": "weight", "label": "重量(kg)", "type": "number", "required": true },
    { "key": "color", "label": "颜色", "type": "select", "options": ["red", "blue", "black"] },
    { "key": "material_grade", "label": "材料等级", "type": "text" }
  ]
}
```

### 8.3 动态属性（dynamic）
**用途**：按属性类型分类的多行key-value属性，支持灵活配置

**数据结构**：
```sql
CREATE TABLE item_attributes (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  item_id BIGINT NOT NULL,               -- 关联物料ID
  attr_type VARCHAR(50) NOT NULL,        -- 属性类型（如：description, specification, custom）
  attr_key VARCHAR(100) NOT NULL,        -- 属性键
  attr_value TEXT,                       -- 属性值
  unit VARCHAR(20),                      -- 单位
  sort_order INT DEFAULT 0,              -- 排序
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_item_type (item_id, attr_type),
  INDEX idx_item_key (item_id, attr_key)
);
```

**数据示例**：
| item_id | attr_type | attr_key | attr_value | unit |
|---------|-----------|----------|------------|------|
| 101 | description | 用途 | 电机驱动部件 | |
| 101 | description | 备注 | 易损件 | |
| 101 | specification | 长度 | 100 | mm |
| 101 | specification | 宽度 | 50 | mm |
| 101 | specification | 电压 | 220 | V |
| 101 | specification | 功率 | 500 | W |
| 101 | custom | 供应商 | ABC公司 | |

**属性类型(attr_type)说明**：
| attr_type | 名称 | 说明 |
|-----------|------|------|
| description | 描述性属性 | 文字描述类属性 |
| specification | 规格属性 | 技术规格参数 |
| custom | 自定义属性 | 用户自定义的扩展属性 |

### 8.4 属性Schema配置
**Schema存储位置**：按物料类型(item_type)配置不同的属性Schema

```sql
CREATE TABLE attribute_schemas (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  item_type VARCHAR(50) NOT NULL,        -- 物料类型（PART/ASSEMBLY/...）
  attr_type VARCHAR(50) NOT NULL,        -- 属性类型（main/description/specification/custom）
  schema_config JSON NOT NULL,           -- Schema定义
  version VARCHAR(2) DEFAULT 'AA',       -- 版本号
  status ENUM('DRAFT', 'RELEASED') DEFAULT 'DRAFT',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_type_version (item_type, attr_type, version)
);
```

**主属性Schema示例**：
```json
{
  "item_type": "PART",
  "attr_type": "main",
  "schema_config": {
    "fields": [
      { "key": "weight", "label": "重量", "type": "number", "unit": "kg", "required": true },
      { "key": "supplier", "label": "供应商", "type": "text" }
    ]
  }
```
