**模块注册机制**：
```go
// internal/core/module/module.go
type Module interface {
    Name() string                          // 模块名称
    Init(container *Container) error       // 初始化依赖
    Routes(r *gin.RouterGroup)             // 注册路由
    Migrations() []migration.Migration     // 数据库迁移（可选）
}

// internal/core/module/registry.go
type Registry struct {
    modules map[string]Module
}

func (r *Registry) Register(m Module) {
    r.modules[m.Name()] = m
}

// internal/modules/user/module.go
type UserModule struct {
    handler    *handler.UserHandler
    service    *service.UserService
    repository *repository.UserRepository
}

func (m *UserModule) Name() string { return "user" }

func (m *UserModule) Init(c *Container) error {
    m.repository = repository.NewUserRepository(c.DB)
    m.service = service.NewUserService(m.repository)
    m.handler = handler.NewUserHandler(m.service)
    return nil
}

func (m *UserModule) Routes(r *gin.RouterGroup) {
    users := r.Group("/users")
    {
        users.GET("", m.handler.List)
        users.POST("", m.handler.Create)
        users.GET("/:id", m.handler.Get)
    }
}
```

**启动入口示例**：
```go
// cmd/server/main.go
func main() {
    registry := module.NewRegistry()

    // 注册所有模块
    registry.Register(user.NewModule())

    registry.Register(workflow.NewModule())

    // 初始化并启动服务

    server.Run()
```

## 4. 数据库设计约束

### 4.1 命名规范
- 表名：小写蛇形复数（如 `users`, `bom_items`）
- 主键：`id` (BIGINT AUTO_INCREMENT)
- 外键：`{table}_id` (如 `user_id`, `material_id`)
- 时间字段：`created_at`, `updated_at`
- 创建人：`created_by`

### 4.2 必备字段
每个业务表必须包含：
```sql
id BIGINT PRIMARY KEY AUTO_INCREMENT,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
created_by BIGINT NOT NULL
```

### 4.3 软删除
- 使用 `deleted_at` 字段实现软删除
- GORM配置：`gorm.DeletedAt`

### 4.4 JSON字段使用规范
- 仅用于扩展属性（`attributes`）
- 不用于核心业务字段
- 前端需要提供Schema定义

### 4.5 数据库连接池配置
```yaml
# config.yaml
database:
  host: localhost
  port: 3306
  name: plm
  user: root
  password: ${DB_PASSWORD}

  conn_max_idle_time: 10m # 空闲连接最大存活时间
```

### 4.6 字符集配置（强制）

### 4.7 事务处理规范
```go
// 单Repository事务：在Service层使用事务
func (s *UserService) CreateUser(req *CreateUserReq) error {
    return s.db.Transaction(func(tx *gorm.DB) error {
        // 在事务中执行多个操作
        if err := tx.Create(&user).Error; err != nil {
            return err
        }
        if err := tx.Create(&userProfile).Error; err != nil {
            return err
        }
        return nil
    })
}

// 跨Repository事务：通过传递tx实现
func (s *BOMService) CreateBOMWithItems(req *CreateBOMReq) error {
    return s.db.Transaction(func(tx *gorm.DB) error {
        // 创建BOM
        bomRepo := repository.NewBOMRepositoryWithDB(tx)
        if err := bomRepo.Create(&bom); err != nil {
            return err
        }
        // 创建BOM项
        itemRepo := repository.NewBOMItemRepositoryWithDB(tx)
        for _, item := range items {
            if err := itemRepo.Create(&item); err != nil {
                return err
            }
        }
        return nil
    })
}
```

```typescript
// router/guards.ts
// 路由元信息定义
interface RouteMeta {
  title: string
  requiresAuth?: boolean      // 是否需要登录
  permissions?: string[]      // 所需权限码
  roles?: string[]            // 所需角色
}

// 路由配置示例
const routes: RouteRecordRaw[] = [
  {
    path: '/material',
    component: Layout,
    meta: { title: '物料管理', requiresAuth: true },
    children: [
      {
        path: 'list',
        component: MaterialList,
        meta: { title: '物料列表', permissions: ['material:view'] }
      },
      {
        path: 'create',
        component: MaterialForm,
        meta: { title: '新建物料', permissions: ['material:create'] }
      }
    ]
  }
]

// 全局路由守卫
router.beforeEach(async (to, from, next) => {
  const userStore = useUserStore()

  // 1. 检查登录
  if (to.meta.requiresAuth && !userStore.isLoggedIn) {
    return next({ path: '/login', query: { redirect: to.fullPath } })
  }

  // 2. 检查权限
  if (to.meta.permissions) {
    const hasPermission = to.meta.permissions.every(p =>
      userStore.permissions.includes(p)
    )
    if (!hasPermission) {
      return next('/403')
    }
  }

  next()
})
```

**权限控制层级**：
1. **路由级**：路由守卫拦截无权限页面
2. **组件级**：v-if="hasPermission('xxx')" 控制元素显示
3. **接口级**：后端接口鉴权（最终防线）

## 6. 后端开发约束

### 6.1 模块间通信规范
```go
// 模块间通过Service接口通信，不直接访问其他模块的Repository

// 1. 在shared/types中定义公共接口
// internal/shared/types/material.go
type MaterialService interface {
    GetByID(ctx context.Context, id int64) (*Material, error)
    GetByIDs(ctx context.Context, ids []int64) ([]*Material, error)
    CheckExists(ctx context.Context, id int64) (bool, error)
}

// 2. 模块实现接口并注册到Container
// internal/modules/material/module.go
func (m *MaterialModule) Init(c *Container) error {
    // 创建service
    m.service = service.NewMaterialService(m.repository)
    // 注册到容器供其他模块使用
    c.RegisterService("material", m.service)
    return nil
}

// 3. 其他模块通过Container获取
// internal/modules/bom/service/bom.go
type BOMService struct {
    bomRepo      repository.BOMRepository
    materialSvc  types.MaterialService  // 接口类型
}

func NewBOMService(bomRepo repository.BOMRepository, container *Container) *BOMService {
    return &BOMService{
        bomRepo:     bomRepo,
        materialSvc: container.GetService("material").(types.MaterialService),
    }
}
```

**通信原则**：
- ✅ 通过接口调用，不依赖具体实现
- ✅ 使用Container管理模块依赖
- ✅ 单向依赖（bom依赖material，material不应依赖bom）
- ❌ 禁止循环依赖
- ❌ 禁止跨模块直接访问Repository

## 7. 安全约束

### 7.1 认证与授权
- JWT Token认证
- Token存储在Redis（支持主动失效）
- Token过期时间：7天
- 敏感操作需要二次验证

### 7.2 密码安全
- bcrypt加密存储
- 密码强度要求：8位以上，包含字母和数字
- 登录失败锁定：5次失败锁定30分钟

### 7.3 接口安全
- 限流：100 req/min per IP
- SQL注入：使用GORM参数化查询
- XSS：前端输入过滤，后端输出转义
- CSRF：Token验证

### 7.4 CORS配置
```go
// Gin中间件配置
func CORS() gin.HandlerFunc {
    return func(c *gin.Context) {
        c.Header("Access-Control-Allow-Origin", getAllowedOrigin(c))
        c.Header("Access-Control-Allow-Methods", "GET,POST,PUT,PATCH,DELETE,OPTIONS")
        c.Header("Access-Control-Allow-Headers", "Content-Type,Authorization,X-Request-ID")
        c.Header("Access-Control-Expose-Headers", "X-Request-ID")
        c.Header("Access-Control-Max-Age", "86400")

        if c.Request.Method == "OPTIONS" {
            c.AbortWithStatus(204)
            return
        }
        c.Next()
    }
}

// 允许的域名（生产环境）
var allowedOrigins = []string{
    "https://plm.example.com",
    "https://admin.plm.example.com",
}
```

**CORS规范**：
- 开发环境：允许 localhost
- 生产环境：白名单域名
- 不使用 `Access-Control-Allow-Origin: *`

**端口映射**：
| 服务 | 容器端口 | 主机端口 | 说明 |
|------|----------|----------|------|
| MySQL | 3306 | 3306 | 数据库 |
| Redis | 6379 | 6380 | 避免与dify的6379冲突 |
| MinIO API | 9000 | 9000 | 文件存储API |

**后端配置连接Redis时使用端口6380**：
```yaml

  port: 6380  # 注意：使用6380而非6379
```

### 8.2 容器化要求
- 每个服务一个Dockerfile
- 多阶段构建（build + runtime）
- 使用Alpine基础镜像
- 非root用户运行

### 8.5 数据备份与恢复
**备份方式**：
1. 停止容器：`docker-compose down`
2. 复制 `docker-data` 目录到备份位置

**恢复方式**：
1. 将备份的 `docker-data` 目录复制回项目根目录
2. 启动容器：`docker-compose up -d`

**注意事项**：
- 确保Docker Desktop在备份/恢复前已停止相关容器
- MySQL和MinIO数据可直接通过文件系统移植
- Redis数据为RDB快照，重启后自动加载

### 11.1 后端日志
```go
// 使用结构化日志（推荐zap或zerolog）
```

### 11.2 前端日志

## 12. 缓存策略

### 12.1 Redis使用场景
| 场景 | Key格式 | 过期时间 | 说明 |
|------|---------|----------|------|
| 用户Session | `session:{user_id}` | 7天 | JWT token存储 |
| 登录验证码 | `captcha:{uuid}` | 5分钟 | 图片验证码 |
| 用户权限 | `perm:{user_id}` | 1小时 | 权限缓存 |
| 物料详情 | `material:{id}` | 10分钟 | 热点数据缓存 |
| 接口限流 | `rate:{ip}:{api}` | 1分钟 | 计数器 |

### 12.2 缓存规范
```
Key命名规范：
- 前缀：业务模块名
- 分隔符：冒号(:)
- 示例：user:info:1, material:list:page1

禁止：
- ❌ 大Key（单值超过10KB）
- ❌ 热Key（单个Key过高QPS）
- ❌ Key永不过期（除非有明确业务需要）
```

### 12.3 缓存更新策略
- **Cache-Aside**：先查缓存，miss则查DB并回写
- **写时失效**：更新DB后删除缓存
- **不使用写时更新**：避免并发脏数据
